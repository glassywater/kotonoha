# 自动日文注音（振り仮名/furigana）设计规格

> 状态:Design / 原型已验证可运行（fugashi + unidic-lite）
> 关联:取代/扩展前面 ruby 标签设计——多数歌词**不含** `<ruby>` 标签，本方案改为**对日文歌词文本运行时做形态素分析，自动为汉字标注平假名读音**

---

## 1. 背景与目标

### 背景
- 上一版设计(`2026-08-15-ruby-furigana-design.md`)假设解析 `<ruby><rt>` 标签。
- 用户确认:**绝大多数歌词不带 ruby 标签**。期望的是对**日文汉字自动加平假名注音**(振り仮名)。

### 目标
- 对渲染的日文歌词，把每个**汉字**(或其汉字成分)上方标注对应**平假名读音**。
- 只影响含汉字的日文行;纯假名行、外来语(片假名)、非日文行完全不变。
- 保持现有 karaoke sweep、翻译、简繁转换、上下文行不回退。
- 不解析也不依赖 `<ruby>` 标签;即便歌词带了标签也能先剥离标签再分析(可选)。

### 非目标(本期)
- 不做字粒度像素级对齐的連見ruby;以「词」为注音单元即可满足读需求。
- 不做中文注音(需要汉字→拼音引擎,超出范围)。
- 不在渲染时实时跑分析(预分析 + 缓存)。

---

## 2. 技术选型

| 部件 | 选择 | 理由 |
|---|---|---|
| 形态素分析器 | **fugashi**(MeCab绑定) | 纯Python、UniDic词典、读音字段完整 |
| 词典 | **unidic-lite** | 轻量、含读音，附在 pip 包，无需额外下载 |
| 假名转换 | 自写(片假名→平假名,±0x60) | 免依赖 |

已验证(本机 .venv-ruby 环境):
- `fugashi.Tagger()` 对 `君の名前は空に消えた` 正确输出:君→キミ,名前→ナマエ,空→ソラ(上下文消歧成功,非クウ)等。
- `.feature` 是 `UnidicFeatures26`,含 `.kana`(读音)、`.orth`(表记)、`.lemma`、`.pos1` 等。
- 外来语 `タワー`、假名 `あなた` 正确不标注;混合词 `見上げ`、`輝く` 汉字部分正确标注。

## 4. 核心算法:从「文本行」到「注音段」

对一行日文歌词(去标签后的纯文本),按以下流水产出「注音段列表」供渲染:

```
文本行
  └─ fugashi.Tagger()  // 词序列: surface + feature.kana
       ├─ 每词: 分 汉字段 / 假同字段 (split_kana_kanji)
       └─ 词含汉字?
            ├─ 否(纯假名/片假名/ASCII) → 无注音,原样
            └─ 是 → 生成 Furigana(base=<拼成的汉字串>, kana=<该词读音>)
```

### 4.1 分段规则 `split_kana_kanji(orth) -> [(文本, 是否汉字)]`
- 汉字= CJK 统一表意(U+4E00–9FFF, U+3400–4DBF)单字符。
- 依序把连续汉字、连续假名/其他 切成段。例:
  - `名前` → `[('名前',真)]`
  - `見上げ` → `[('見上',真),('げ',假)]`
  - `消え` → `[('消',真),('え',假)]`

### 4.2 注音单元
- 以一个「词」含汉字的段集合为一个注音单元:
  - base = 所有汉字段拼接(如 `綺麗`,`桜`,`見上`,`美`)
  - kana = 该词的 `feature.kana` 片假名转平假名(如 `きれい`,`さくら`,`みあげ`,`うつくしく`)
- **只对含汉字的段标注音**;送假名(`げ`/`え`)、纯假名、外来语不标。
- base 逐字对应 kana 的精细分配(如 `東京`→`とうきょう` 是否要 `東→とう`/`京→きょう`)本期末必做——以词为单位整标在上方即可读。后续可按词内逐字对齐,见 §7。

### 4.3 数据结构(临时,渲染用)

```python
@dataclass(frozen=True)
class Furigana:
    base: str          # 汉字串,如 "名前" / "見上"
    kana: str          # 平假名读音,如 "なまえ" / "みあげ"
    # base 在整行纯文本 text 中的起始字符偏移(用于 sweep/光标对齐)
    pos: int
```

一行 → `list[Furigana]`(可能空)。

## 5. 数据模型改动

沿用上版思路,保持向后兼容。为了**不破坏现有 LyricWord**,建议:

- 行/词上**不新增持久字段**保存注音(避免侵入 model 和简繁转换路径)。
- 改为在**渲染层**对 `LyricLine.text` 预分析出 `list[Furigana]`,缓存于 label 实例(测到 line 变化时重建)。
- 这样 model、解析器、sqlite 缓存、简繁转换**零改动**——Furigana 是渲染期视图,不进磁盘。

好处:最小侵入;简繁转换后文本变了,注音基于**转换后的显示文本**重新分析即可(用户看什么就标什么)。

## 6. 渲染层:KaraokeLabel

核心改动仍在 `karaoke_label.py`,但比 ruby 标签版更简单——**不需要逐字 ruby**,而是整词上方一小行假名。

### 6.1 额外字体
- 需要一个注音小字体:同主字族,`pixelSize` ≈ 主字的 45–55%,`QFont` 继承自 `current_font` 但改小(可用 `QFont(current_font)` clone 后 setPixelSize)。缓存 `_fm_furigana = QFontMetrics(ruby_font)`。

### 6.2 布局 `_rebuild_layout`
- 对含注音的行,逐「渲染单元」测量:
  - 单元 = 普通假名/标点串 或 一个注音词(base+kana)。
  - 段宽 = 对注音单元取 `max(base 宽, kana 宽)`;普通单元取文本宽。
  - `_total_w` = 各段宽之和;`_word_widths` 相应改为段宽序列,供 sweep 推进。
- 行高:注音需要上方额外空间,`_band_height`/`sizeHint` 增加一个注音行高(如 `int(main*0.6)`)。

### 6.3 绘制 `paintEvent`
- 对普通单元:原样 `drawText`。
- 对注音单元:
  1. 主字 base 用主字体、正常位置(左对齐该段),参与 sweep 颜色/渐变。
  2. 注音 kana 用小字体、画在 base 上方(段内水平居中对齐或靠左),随段 alpha 联动。
  - shadow / glow / sweep / pop 各步骤能复用 `_draw_furigana_seg`(“画一个注音段”),把 base 与 kana 一并画。
- 无注音行走**原路径零改动**。

### 6.4 Sweep
- `_compute_sweep` 用段宽推进;注音段的唱法(未唱/唱中/唱完)由主字承担,kana 跟随段 alpha。逐字 YRC 时若注音词含多个 YRC 字,近似保持整词一体。

## 7. 可选增强(后续)

- **逐字分配**:`東京`→`東`(とう)+`京`(きょう),或 `見上げ`→`見`(み)+`上`(あ)+`げ`。需要按 kana 音位与 base 分片对齐的启发(或直接用 Sudachi/UniDic 的 `base`+`kana` 再拆)。本期先整词标注。
- **注音开关**:Settings 加「日文注音」开关与字号。
- **只对行首/主旋律行标注**,上下文行是否标注可配。
- **缓存**:同 `LyricLine` 的 `text + lyrics_script` 作 key,`lru_cache` 注音结果避免反复跑分析。
- **懒加载 tagger**:`fugashi.Tagger()` 初始化耗时(~百ms),启动时惰性初始化一次,或用单例。

---

## 8. 失败与边界

- 非日文/纯 ASCII 行:`split_kana_kanji` 无汉字 → 无注音,零开销。
- 分析器异常(词典缺失):捕获后整行回退纯文本,不崩。
- 注音比 base 宽:段内靠左,不居中。
- 缓存 key 含转换后文本,避免简繁不一致。
- 性能:60fps 绘制只用缓存的段布局,分析在 line 变化时 + 缓存命中时不做。
